投影 [第二部分-讲义.html](./第二部分-讲义.html)。分支「第二部分」，没有改良版。老师演示，学生下载代码对照页面、代码、数据库看。

课前：老师电脑上 MySQL 和 Adminer 在 Docker 里，前端切到「第二部分」起在 5173。Adminer 里准备好 A-01-01 上 10 个垫圈（第一部分的入库案例）。

## 启动

开关在 `src/main/resources/application.yaml` 的 `app.lesson`。进程启动时读一次，改完必须重启，控制台出现 `Started ProSkillApplication` 再操作页面。这节课用两个：

- `optimistic-lock`：默认 `on`。更新库存时带上读到的 `version`，对不上返回 `STOCK_CONFLICT`。第二次课演示丢失更新时改成 `off`，只按 id 改数量。
- `outbound-read-pause-ms`：默认 `0`，读完数量后不停。第二次课设成 `3000`，让两个请求都读到同一个旧数。做完改回 `0`。

MySQL 和 Adminer：

```bash
docker compose -f docker-compose.dev.yml up -d mysql adminer
```

本机 8080 被别的程序占着，后端开在 8088。前端在前端文件夹，请求转到 8088：

```bash
VITE_PROXY_TARGET=http://localhost:8088 npx pnpm@9 dev
```

后端在后端文件夹。第一次课用默认开关：

```bash
./mvnw spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8088"
```

第二次课演示丢失更新（乐观锁关掉，读完数量停 3 秒）：

```bash
./mvnw spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8088" -Dspring-boot.run.arguments="--app.lesson.optimistic-lock=off --app.lesson.outbound-read-pause-ms=3000"
```

打开乐观锁再做一遍（停顿留着）：

```bash
./mvnw spring-boot:run -Dspring-boot.run.jvmArguments="-Dserver.port=8088" -Dspring-boot.run.arguments="--app.lesson.outbound-read-pause-ms=3000"
```

做完用第一次课那条命令重启，两个开关回到 yaml 里的默认值。

## 第一次课（2 课时）：出库

1. 第 1 节（约 10 分钟）：出库页走一遍，指出完成时要减库存、不够要拒绝。
2. 第 2 节（约 10 分钟）：四张表，重点说 `inventory.version` 是干什么的，留到第二次课。
3. 第 3 节（约 70 分钟）：案例。出 4 个，每一层停在截图上讲；再出 20 个，看 400 停在 Service 哪一行；最后到 Adminer 看 10 变成 6、version 变成 1。

## 第二次课（4 课时）：并发

1. 第 4 节（约 60 分钟）：先在黑板上画那张时间表。用上面「丢失更新」那条命令重启，A-01-02 上放 1 个，页面勾选两张单「同时完成」，两张都成功；到 Adminer 看库存 0、version 0；控制台里两句「读到数量 1」。
2. 第 5 节（约 60 分钟）：讲 Service 第 91–96 行和 Mapper 第 52 行。用上面「打开乐观锁再做一遍」那条命令重启，再做一遍，一张 STOCK_CONFLICT；Adminer 里 version 是 1。
3. 第 6 节（约 30 分钟）：改行和流水不展开，指给学生看代码在哪。
4. 第 7 节和答疑（剩余时间）。做完用第一次课的默认命令重启，把 `outbound-read-pause-ms` 去掉。
